# 11 — Internationalization (i18n)

English + Bengali from Phase 1 for marketing and customer-facing UI.

## Setup

Use **next-intl** with App Router:

```
src/
├── i18n/
│   ├── config.ts          # locales: ['en', 'bn']
│   ├── index.ts           # getMessage() helper
│   └── messages/
│       ├── en.json
│       └── bn.json
```

(next-intl `request.ts` / `routing.ts` added when wiring App Router in Phase 1.)

## Locale routing

| Approach | Path |
|----------|------|
| Marketing | `/en/...` and `/bn/...` OR cookie/header without prefix |
| Portal | User preference in localStorage `ipb_locale` |

**Default:** `en` with toggle in marketing nav and customer header.

## Translation file structure

```json
{
  "common": {
    "save": "Save",
    "cancel": "Cancel",
    "delete": "Delete",
    "loading": "Loading..."
  },
  "marketing": {
    "hero": {
      "title": "Run your whole ISP from one operator's console",
      "titleBn": "পুরো ISP চালান একটি অপারেটর কনসোল থেকে"
    }
  },
  "customer": {
    "dashboard": {
      "title": "Dashboard",
      "expiryBanner": "Your subscription expires on {date}"
    }
  },
  "admin": {
    "customers": {
      "title": "Customers",
      "addCustomer": "Add Customer"
    }
  }
}
```

Mirror Bengali strings from PHP landing partials (`lp-lang--bn` spans in `hero.php`, etc.).

## Font switching

When `locale === 'bn'`:

```tsx
<body className={locale === 'bn' ? 'font-bengali' : 'font-sans'}>
```

CSS:

```css
.font-bengali {
  font-family: var(--font-bengali);
}
```

## Scope by phase

| Phase | i18n scope |
|-------|------------|
| P0 / foundation | Message files scaffolded: `src/i18n/messages/en.json`, `bn.json` |
| Phase 1 | Wire next-intl + marketing toggle |
| Phase 3+ | Customer + admin strings expand same JSON |

**Messages ready now:** import via `@/i18n` → `getMessage('bn', 'marketing.hero.title')` until next-intl is wired.

| Phase | Scope |
|-------|--------|
| 1 Marketing | Full EN + BN |
| 3 Customer | Full EN + BN |
| 4–6 Admin | EN only initially; BN labels for customer-facing fields OK |
| 7 | Admin BN optional |

## RTL

Not required (Bengali uses LTR).

## Date/number formatting

```typescript
import { useFormatter } from 'next-intl';

const format = useFormatter();
format.number(1500, { style: 'currency', currency: 'BDT' });
format.dateTime(new Date(), { dateStyle: 'medium' });
```

## Language toggle component

```tsx
// components/shared/LocaleToggle.tsx
// Toggle EN | বাং — persists to localStorage, refreshes messages
```

Place in:
- Marketing nav (top right)
- Customer header
- Optional admin header

## Do not hardcode user-facing strings

❌ `<h1>Customers</h1>`  
✅ `<h1>{t('admin.customers.title')}</h1>`

Exception: mock data values (customer names, addresses) stay as-is in mock files.
